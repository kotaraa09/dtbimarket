# docs

| Folder | What goes here | What does not |
|---|---|---|
| `00-archived` | Superseded documents, moved not deleted | Anything current |
| `01-requirements` | What we build and why; course requirement mapping | How we build it |
| `02-design` | Architecture, data model, API contracts, UI flows | Research design |
| `02-design/decisions` | ADRs — one file per irreversible choice | Reversible preferences |
| `03-research` | Hypotheses, experiments, analysis plan, findings | Feature specs |
| `04-testing` | Test strategy, manual scripts, known gaps | Test code |
| `05-retrospectives` | What went wrong and what changed because of it | Blame |
| `06-log` | Dated one-line working entries, append-only | Long narrative |
| `07-delivery` | Thesis chapters, slides, demo scripts, submissions | Drafts in progress |
| `08-operations` | Runbooks, deployment, incidents, seller onboarding | Design rationale |

Naming: `YYYY-MM-DD-short-title.md` for anything tied to a date. Documents that are maintained rather than dated keep a stable name — `hypotheses.md`, `analysis-plan.md`, `feature-list.md`. Documents with an identity of their own carry their ID: ADRs `NNNN-short-title.md`, experiments `EXP-NNN-short-title.md`, user journeys `UJ-NN-short-title.md`, test specs `TS-NN-short-title.md`, prototypes `PR-NN-short-title.html` with a `.md` of the same name beside it.
