dtbimarket Architecture & Data Model architecture.md · database-schema.md

Every user action passes through one API

Three placement rules

  • Events are written by the API, inside the action's transaction. Never by the browser.
  • Assignment happens on the server, once, persisted. Unique per unit.
  • Metrics live in one module, read by both the dashboard and the advisor.

Conventions

  • Event has no foreign keys — a deleted product must not erase the measurement
  • Money in integer satang — float totals stop adding up
  • is_seed on every table — demo rows excluded everywhere
  • OrderItem stores price and name — later edits never rewrite history

acted = event(store, action_type) <= delivered_at + 7 days
