# 2026-09

2026-09-03  First code in the repository. M0 foundation (PB-01 monorepo, PB-02 Prisma schema, PB-03 `Event` + emitter, PB-05 seed) and most of M1 (PB-06 seller auth, PB-07 store profile, PB-08 product CRUD, PB-09 publish/unpublish, PB-11 price/stock) — all with their events, plus Next.js pages for each. 33 tests pass. D-2 decided and written up as ADR-0003.

2026-09-03  D-2 decided: server-side session, not JWT. The argument that settled it was not the usual one about `localStorage` being script-readable — it was revocation. A seller who withdraws from the study has to be signable-out, and a self-contained token cannot be taken back. Sessions are a table; `node:crypto` HMAC signs the ID into an httpOnly cookie. No session library (rule 10).

2026-09-03  Append-only enforcement needed a fourth mechanism, not three. ADR-0001 says the application refuses, the database role has no `UPDATE`/`DELETE` grant, and review looks for it. But **a table's owner bypasses its own grants**, and in local development and the simplest managed-Postgres setups the app connects as the owner — so the grant was protecting nothing here. Added a `BEFORE UPDATE OR DELETE` trigger that raises regardless of who is connected, and kept the grants for deployments with a separate role. Verified by test: both statements now fail with the rule quoted in the error.

2026-09-03  Found and fixed a data-integrity bug the hard way: an action taken on a **seed** store was writing `is_seed = false` events. Every analysis query and every seller-facing metric would have counted demo activity as real, and the only reason it surfaced was checking the table after clicking through the UI rather than trusting the 200. `is_seed` now propagates from the acting store (or user, before a store exists) into the event. One wrong row from before the fix is still in the local dev database and always will be — which is the append-only lesson at one row's cost, so it is being kept rather than reset away.

2026-09-03  `parseBahtToSatang` accepted `"12,"` as 12 baht. It stripped every comma and then validated, so any comma placement passed. Caught by a test written for the round-trip property, not by anything anyone noticed on screen. Now the separators have to be in valid thousands positions or the input is refused. Money bugs do not throw; they just make a seller's totals disagree with their own arithmetic.

2026-09-03  The seed script has its own `event` writer, which is a second insert path and ADR-0001 says there is exactly one. It cannot import `emitEvent` — that lives in `apps/api`, and `packages/db` depending on `apps/api` would invert the dependency that makes the API the choke point. The seed writer calls the same `assertNoPersonalData` guard and can only write `is_seed = true`. **Flagged for a decision:** either accept it as written, or move `emitEvent` into `packages/db` so there genuinely is one path. Not decided alone because ADR-0001 is explicit.

2026-09-03  Payload safety is an allowlist per event type (`packages/shared/src/event-payloads.ts`), not a scan for personal-looking values. `detailed-design.md` called for this and it is the right shape: an allowlist rejects the key nobody thought about, which is the one that leaks. A banned-fragment check sits behind it for the likelier mistake — someone editing the allowlist carelessly once it is trusted.

2026-09-03  Design tokens for the web app were copied verbatim out of `PR-01-seller-dashboard.html` rather than re-picked, so the built pages and the prototype that was reviewed cannot drift. The prototype stays the place a token changes first.

2026-09-03  Toolchain notes for next time. `corepack enable` needs an admin shell on this machine; `npm i -g pnpm` works. pnpm 11 moved `onlyBuiltDependencies` into `pnpm-workspace.yaml` as an `allowBuilds` map, and Prisma generates nothing until those postinstall scripts are permitted. Prisma's legacy `prisma-client-js` generator cannot place its output under pnpm's isolated `node_modules`; the newer `prisma-client` generator with an explicit `output` works. Windows `curl` mangles Thai in an argument before sending it — the API was fine, the test client was not, which cost twenty minutes of looking in the wrong place.

2026-09-03  Near-miss on rule 9. `.gitignore` listed `.env`, `.env.local` and `.env.*.local`, so the `.env.test` created for the integration-test database — which holds a real `SESSION_SECRET` — was untracked but **not ignored**, one `git add -A` away from being committed. Now `.env.*` is ignored wholesale with the two value-less templates allowed back by name. A denylist of specific filenames misses whichever one gets created next; that is the general lesson, not the specific file.

2026-09-03  D-3 decided and PB-10 built — product photos, the last piece of M1. Written up as ADR-0004: an S3-compatible bucket behind one adapter, MinIO locally and a managed bucket in deployment, with the **provider left as configuration** so it can be chosen together with D-1 rather than constraining it. `product.photo_added` now comes from a real upload path, which means the event the thesis's primary metric joins on is finally being produced by the thing it is supposed to measure. 11 new tests; 44 in total.

2026-09-03  Q-2 deliberately NOT closed. Object storage was the leading candidate for the coursework external-API requirement and it would have been easy to declare it satisfied while writing the ADR. The owner chose to keep Q-2 open and pick an external API separately, so ADR-0004 says in as many words that it does not answer REQ-H2, and FEAT-H2 / PB-27 stay blocked. Worth noting because a decision that quietly widens to close an adjacent open question is exactly the kind of thing that is discovered in a viva.

2026-09-03  No upload library. Node's own `Response.formData()` parses multipart, so `multer` and `busboy` were both unnecessary (REQ-N4). Checked before designing around it rather than after. Same for the seed's placeholder images: `node:zlib` has `crc32`, so a solid-colour PNG is about twenty lines and needs no image library.

2026-09-03  Bug found in testing, not in review: an oversize upload was destroying the socket, so the client saw a connection reset instead of the 413 that `api-spec.md` specifies. A seller uploading a 6 MB photo from their phone would have been told "something went wrong" rather than "your photo is too big". The fix is to drain the request instead of destroying it — a client mid-upload cannot read a response on a socket that has already been torn down. Now rejected on `Content-Length` where it is honest, with a streaming cap as the backstop and a hard limit before the connection is genuinely abandoned.

2026-09-03  Making photos real broke the seed. Seeded `ProductPhoto` rows pointed at storage keys with no object behind them, which was harmless while nothing rendered them and became broken thumbnails the moment PB-10 landed — in exactly the demos and screenshots `database-schema.md` says the seed exists to make safe. The seed now writes real placeholder objects. Verified by seeding a throwaway database rather than resetting the development one: 10 rows, 10 objects, then dropped. **The existing local dev database still has the old rows**; `pnpm db:reset && pnpm db:seed` fixes it whenever convenient.

2026-09-03  Upload validation ignores what the client says the file is. REQ-N27 asks for content-type verified server-side, and the tempting reading is to check the multipart part's `Content-Type` header — which the client writes, so it proves nothing. The format is decided from magic bytes; a shell script named `evil.png` and declared `image/png` is refused, and there is a test that says so.
